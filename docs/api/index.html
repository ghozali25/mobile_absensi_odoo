Ali Attendance API

Dokumentasi endpoint modul Odoo 18 ag_rest_api untuk aplikasi mobile Ali Attendance. Dibangun otomatis dari kode modul + contoh respons di docs/mocks/ — setiap endpoint di bawah ini punya contoh request & respons yang sama persis dengan kontrak aslinya.

Base URL: https://odoo18.hiddenlab.me  ·  Semua endpoint:  ·  Versi modul: 18.0.1.2.33

Koleksi Postman · Mock server (coba tanpa Odoo) · Repo aplikasi

Auth — wajib dibaca

  1. Login: POST https://odoo18.hiddenlab.me/ag_rest_api/v1/auth/token dengan body {"db": "...", "login": "...", "password": "..."}. Server menjawab token Bearer + masa berlakunya + info user.
  2. Semua request berikutnya memakai header Authorization: Bearer <token> (bukan cookie sesi).
  3. Tanpa token valid: JSON {"status": "error", "code": "NO_TOKEN" | "INVALID_TOKEN" | "TOKEN_EXPIRED"} dengan HTTP 401 — bukan redirect HTML. Token kedaluwarsa → login ulang.
  4. Logout: POST /ag_rest_api/v1/auth/logout dengan header Bearer — token pemanggil dicabut.

Token hanya disimpan sebagai hash SHA-256 di database; masa berlaku default 30 hari (Settings → Attendances → Masa Berlaku Token).

Format

  • Request: POST /ag_rest_api/v1/<endpoint> dengan body JSON (boleh kosong). Empat endpoint memakai GET (foto, fitur, tracking live).
  • Sukses: {"status": "success", "message": "...", "data": {...}}
  • Gagal: {"status": "error", "code": "KODE", "message": "..."}
  • Waktu: string UTC "YYYY-MM-DD HH:MM:SS" (aplikasi mengonversi ke WIB).

Coba tanpa Odoo (mock server)

Unduh mock-server.py, jalankan python3 mock-server.py — server mock jalan di http://localhost:8072 dan melayani semua 72 endpoint dengan contoh respons di halaman ini. Login mock menerima db/login/password apa saja dan mengembalikan token demo; endpoint lain menerima Bearer token apa saja (tanpa header → 401 NO_TOKEN, sama seperti server asli).
